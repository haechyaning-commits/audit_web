# 공공감사데이터 포트폴리오 — 개발 진행 계획 (WBS) v3

> v1 대비 변경점: **8월 31일 완성**이라는 마감이 정해짐에 따라, "다 만들기"에서 "마감 안에 확실히 보여줄 것부터 만들기"로 우선순위를 다시 짬.
> 오늘(2026-08-05) 기준 마감까지 약 4주.
> v3 변경점: **4줄 요약을 1주차 배치로 미리 다 만드는 방식에서 제외** — 72,913건 전체를 미리 요약하면 실제로 조회되지 않을 문서까지 비용/시간(실측 약 7.2시간)을 쓰게 됨. 대신 **상세 API에서 온디맨드 생성 + DB 캐싱**(처음 조회될 때만 생성해서 저장, 이후엔 캐시 재사용)으로 변경 — 2주차 상세 API 구현에 자연스럽게 포함됨. 근거는 `docs/architecture.md` §4.5 참고.

## 이번 계획의 원칙

1. **먼저 "다 되면 뭘 보여줄 것인가"부터 정한다** (아래 참고)
2. **눈에 보이는 결과가 가장 빨리 나오는 순서로 진행한다** — 완벽한 설계보다 "돌아가는 것"이 먼저
3. **리랭커, 한국어 형태소 분석 정교화, 품질 테스트는 필수가 아니라 "시간 남으면 추가하는 것"으로 뺀다** — 없어도 검색 자체는 작동함. 나중에 추가해도 지금 만드는 구조를 다시 뜯을 필요 없이 얹을 수 있게 설계돼 있음(`docs/architecture.md` §3.4, §3.6 참고)
4. **매주 일요일, 이번 주 목표를 달성했는지 체크한다.** 못 했으면 다음 주는 스트레치 항목부터 자동으로 잘라낸다

## 8월 31일까지 "완성"의 기준 (Definition of Done)

아래 4가지가 되면 완성입니다. 그 이상은 여유 되면 추가하는 것이지 필수가 아닙니다.

- [ ] 실제로 인터넷에서 접속 가능한 링크가 있다 (Vercel + Railway 배포)
- [ ] 검색창에 궁금한 걸 자연어 문장으로 입력하면 관련 감사 사례 카드들이 추천된다
- [ ] 카드를 클릭하면 상세페이지로 가서 **4줄 요약이 먼저 보이고**, 원문은 펼쳐야 나온다
- [ ] README에 "왜 이렇게 만들었는지" 스토리가 정리되어 있다

> 이건 설계가 잘못됐다는 뜻이 아니라, **"다 넣고 못 끝내는 것"보다 "핵심만 넣고 끝내는 것"이 낫다**는 판단입니다. 시간이 남으면 스트레치 목록 중 위에서부터 추가합니다.

## 주차별 계획

### 1주차 (8/5 화 ~ 8/10 일) — 데이터가 검색 가능한 상태로 DB에 들어가기

| 할 일 | 완료 기준 |
|---|---|
| 콜랩 임베딩 마무리 | embeddings.npy 파일 완성 |
| DB 테이블 설계 (documents, chunks) | 스키마 확정 |
| pgvector 적재 스크립트 작성·실행 | DB에 임베딩까지 다 들어감 |
| ~~4줄 요약 배치 실행~~ *(v3에서 제외 — 2주차 상세 API에 온디맨드 생성으로 흡수)* | — |

**이번 주 목표(체크포인트)**: DB에 SQL 쿼리 하나 날려보면 비슷한 사례가 순위대로 나온다 (프로그램 없이 DB 화면에서 확인)

### 2주차 (8/11 월 ~ 8/17 일) — 검색이 API로 나오기

| 할 일 | 완료 기준 |
|---|---|
| FastAPI 프로젝트 세팅 | 서버 켜짐 |
| 검색 API 구현 (RRF만, 리랭커 없이) | 검색어 넣으면 결과 JSON 나옴 |
| 상세 API 구현 (원문 + 4줄 요약, **온디맨드 생성+DB 캐싱**) | 문서 ID 넣으면 상세 내용 나옴. 요약이 비어있으면 그 자리에서 OpenAI로 생성 후 DB에 저장, 이후 같은 문서는 저장된 값 재사용 |

**이번 주 목표**: Postman이나 브라우저 주소창으로 검색 API를 호출하면 결과가 나온다 (화면 없이 데이터만)

### 3주차 (8/18 월 ~ 8/24 일) — 눈에 보이는 화면 완성

| 할 일 | 완료 기준 |
|---|---|
| 검색페이지 (자연어 검색창 + 추천 결과 카드) | 문장으로 검색하면 화면에 카드 뜸 |
| 상세페이지 (4줄 요약이 메인, 원문은 "펼쳐보기" 토글, 신뢰도 배지) | 카드 클릭하면 요약 먼저 보이고, 원문은 눌러야 펼쳐짐 |
| 로컬에서 전체 흐름 확인 | 내 컴퓨터에서 검색→상세까지 다 됨 |

**이번 주 목표**: 노트북 화면으로 남한테 시연 가능한 수준이 된다 (아직 배포 전, 내 컴퓨터에서만)

### 4주차 (8/25 월 ~ 8/31 월) — 배포 + 마무리

| 할 일 | 완료 기준 |
|---|---|
| Railway(백엔드/DB), Vercel(프론트) 배포 | 인터넷 주소로 접속됨 |
| 버그 수정, 자잘한 다듬기 | 이상한 결과·에러 없음 |
| README 작성 (스토리 + 스크린샷) | 포트폴리오로 제출 가능한 문서 |
| **시간 남으면**: 스트레치 목록 위에서부터 1~2개 추가 (한국어 형태소 분석 추천, 리랭커보다 체감 효과 큼) | 여유 될 때만 |

**최종 목표(8/31)**: 위 "완성의 기준" 4가지 전부 체크
