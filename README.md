## 검색은 어떻게 동작하나

1. 사용자가 입력한 문장을 벡터로 변환
2. 벡터 검색(의미 기반)과 키워드 검색을 각각 수행
3. 두 결과를 RRF(Reciprocal Rank Fusion)로 합쳐서 최종 순위 결정
4. 같은 문서 중복 노출 방지(document 단위 dedup) 후 Top-10 반환

## 주요 설계 결정 (왜 이렇게 만들었나)

전체 목록은 `docs/architecture.md` §5.6 ADR 표 참고. 대표적인 것 몇 가지만 요약:

- **스코어링에 RRF를 쓴 이유**: 벡터 유사도와 키워드 검색 점수는 스케일이 달라 단순 합산하면 한쪽이 항상 우세해짐. 순위 기반으로 합치면 이 문제에서 자유로움
- **검색 단위는 청크, 상세 단위는 문서**: 유사사례 검색 시 관련 없는 부분까지 섞이는 노이즈를 막고, 상세페이지는 원문 전체 맥락이 필요하기 때문
- **4줄 요약 구조를 고정한 이유**: 자유형식 요약은 출력 편차가 커서 화면 표시가 불안정해짐
- **4줄 요약을 미리 다 안 만들고 온디맨드로 만든 이유**: 전체 문서(약 7만 건)를 미리 배치로 요약하면 실제로 조회되지 않을 문서까지 비용·시간을 쓰게 됨. 상세페이지 최초 조회 시에만 생성해서 DB에 저장(캐싱)하고, 그다음부터는 캐시된 값을 재사용
